# CLAUDE.md — StoneWorld

Пульт проекта. Здесь только то, что нужно в каждой сессии. Полные требования — `/Documentation/PRD.md`, читать по ссылкам из раздела 9.

---

## 1. Проект

Премиальный одностраничный лендинг компании по укладке каменного ковра плюс техническая страница «Политика конфиденциальности».

Сборка идёт на чистом HTML/CSS/JS в `/root` («цех»), затем нарезается по секциям и переносится в Тильду. **Vanilla-код продакшеном не является** — это материал под нарезку.

Критерий любого решения: **переживёт ли оно вставку в блок T123 Тильды.** Если нет — решение неверное, каким бы хорошим оно ни было само по себе.

Основной референс — `nphouse.ee/ru/paving`. Гамма, объём анимаций, плотность контента, компоновка GlobalHeader. Полностью — PRD 5.7.1.

Тариф Тильды оплачен, домен подключён, хостинг решён. Эти вопросы не поднимать.

## 2. Терминология

Одна сущность — один термин. Синонимы не использовать ни в коде, ни в документации, ни в текстах сайта.

| Термин | Значение |
|---|---|
| **Заказчик** | Компания StoneWorld, для которой делается сайт |
| **Клиент** | Посетитель сайта. Не «пользователь», не «лид» |
| **Позиция** | Один из 20 видов покрытия. Не «товар», не «продукт» |
| **Карточка** | Визуальное представление позиции в каталоге |
| **Секция** | Изолированный модуль страницы, будущий отдельный блок Тильды |
| **Цех** | Vanilla-сборка до переноса в Тильду. Не продакшен |
| **Каменный мир** | Название компании в текстах сайта, разметке, `aria-label` и JSON-LD |
| **StoneWorld** | Домен, имя проекта, внутреннее имя в документации. Клиенту не показывается |

Всё, что видит клиент, — «Каменный мир». Всё, что видим только мы, — StoneWorld. Ошибка тихая: ни ошибки в консоли, ни визуального дефекта, но разметка разойдётся с логотипом и с названием юрлица. Полностью — PRD 1.

## 3. Стоп-лист

Нарушение любого пункта ломает перенос в Тильду. Проверяется на шаге 11.

- **Сборщики и фреймворки**: React, Vue, Webpack, Vite, ESM, `import`. Код обязан работать вставленным в T123 как есть, без шага сборки.
- **Глобальные CSS-селекторы**: `body`, `*` в корне таблицы стилей, голые `a`, `h1`–`h6`, `p`, `ul`. Заденут всю страницу Тильды и соседние блоки. Потомковый `*` внутри контейнера секции (`.sw-header *`) глобальным **не считается** — он не выходит за пределы секции, см. раздел 4. Единственное разрешённое правило по `body` живёт в лесах цеха и в Тильду не едет.
- **Сброс стилей** — reset, normalize, любые правила «на всякий случай». В Тильде их не будет, а секция, которая на них молча оперлась, поедет по вёрстке.
- **Свой `@font-face`.** Шрифт подключается настройками сайта Тильды, см. раздел 5.
- **Классы с префиксом `t-` и `tn-`** — зарезервировано движком Тильды. Это же касается классов, которые генерирует SplitText: имена задаются явно с префиксом секции.
- **Глобальные JS-переменные.** Весь код секции — в IIFE.
- **jQuery.** Тильда перешла на чистый JS и для новых проектов jQuery не подключает.
- **Относительные пути к ассетам** и любые пути, завязанные на структуру цеха. Исключение — леса цеха, они не переносятся.
- **Общее состояние между секциями.** Исключений ровно два, оба описаны в разделе 6. Третьего не заводить.
- **Иконки.** Все иконки лежат в `/Design_system/Icons` и берутся оттуда. Не рисовать вообще, включая SVG-заглушки и плейсхолдеры. Нужной иконки в папке нет — описать словами какая, остановиться и ждать пользователя.
- **PHP** — T123 не поддерживает.
- **Свой бэкенд приёма заявок.** Форма при переносе становится нативным блоком Тильды.

## 4. Обязательные правила кода

**CSS**
- БЭМ с префиксом секции: `sw-hero__title`, `sw-catalog__card--featured`.
- Стили секции обёрнуты в её контейнерный селектор и за его пределы не утекают.
- `box-sizing` объявляется **посекционно**, первой строкой стилей:

```css
.sw-header,
.sw-header *,
.sw-header *::before,
.sw-header *::after { box-sizing: border-box; }
```

Потомковый `*` внутри контейнера DOM Тильды не трогает. Одно правило в head было бы глобальным `*` из стоп-листа, а расчёт на сброс самой Тильды непроверяем и вылезет только на опубликованной странице.

- Сброса стилей в проекте нет. Каждый элемент задаёт свои `margin`, `padding`, `list-style`, `text-decoration` явно, через собственный класс `sw-*`.
- `var()` всегда со вторым аргументом. Значения фолбэков — из `design_system.md` раздел 2, без отсебятины.
- В `@media` — литеральные px. `var()` там не работает.
- **Граница перестроения — 768px включительно.** Компактное состояние `max-width: 768px`, десктопное `min-width: 769px`. Вариантов `767 / 768` в проекте нет: расхождение по границе даст разные точки перестроения у соседних секций. То же в `gsap.matchMedia()`.

**JS**
- IIFE на каждую секцию. Неймспейс — только один и только если без него действительно нельзя.
- Секция проверяет наличие своих DOM-узлов и тихо ничего не делает, если их нет.
- Секция не зависит от порядка выполнения других блоков и переживает перемещение в редакторе.
- Перед использованием библиотеки проверять её наличие (`if (!window.gsap) return;`). Библиотеки нет — секция деградирует тихо, страница не падает.

**Разметка**
- `alt` заполнен у всех изображений. Для каталога alt собирается по шаблону: `Каменный ковёр {название} - укладка в Сочи и Краснодаре`.
- `loading="lazy"` везде, кроме первого экрана. Lazy Load Тильды работает по её собственной разметке и наших изображений не касается.
- Все ассеты — по абсолютным URL (файлохранилище Тильды или стабильный CDN).
- Комментарии расставлены так, чтобы при нарезке граница «это стиль / это поведение / это разметка» была очевидна.

**Каркас цеха**

Файл один: `/root/index.html`. Это эмуляция страницы Тильды, а не продакшен: каждый его кусок уезжает в конкретное место платформы. Зоны помечены баннерами-комментариями и при нарезке разбираются целиком.

| Зона | Куда едет |
|---|---|
| `ЗОНА A — HEAD САЙТА` | «Настройки сайта» → «Ещё» → «HTML-код внутрь head»: `:root` с токенами, подключение библиотек |
| `ЗОНА B — СЕКЦИИ` | Каждая секция — один блок T123: `<style>` и разметка вместе |
| `ЗОНА C — СКРИПТЫ` | Блоки T123 в самом низу страницы. JS всех секций живёт здесь, а не рядом с разметкой |
| `ЛЕСА ЦЕХА` | Не едет никуда: `@font-face` цеха, правило по `body`, растяжка пустых контейнеров. Лежит в `<head>` сразу после зоны A |
| `ПРАВИЛА СБОРКИ` | Не едет и не удаляется — отдельная категория, шапка в самом верху файла |

- Леса стоят в `<head>`, а не в конце документа: селектор `[data-sw-scaffold]` имеет ту же специфичность, что `.sw-catalog`, и снизу перебивал бы собственные правила секции. Плюс в продакшене `@font-face` объявляется в head — цех обязан эмулировать продакшен, а не отличаться от него.
- Пустой контейнер секции помечен атрибутом `data-sw-scaffold`. Атрибут снимается при сборке секции вместе с растяжкой `min-height` из лесов. В перенесённом коде его быть не должно.
- Порядок в DOM: GlobalHeader первым, дальше по PRD 5.3. Очередь **сборки** — другая, она в таблице «Полный состав сайта» там же. Не путать: ID секции, номер в очереди сборки и позиция в DOM — три разные вещи.
- Цех открывать локальным HTTP-сервером. Через `file://` Chrome не загрузит шрифт (opaque origin) и покажет фолбэк-стек — выглядит это как «шрифт не подключился».

**Размещение в Тильде**
- Приоритет решений: (1) наш код в T123 → (2) готовый T-блок → (3) Zero Block, только если первые два не тянут.
- Основной референс сделан на Тильде, часть его решений — готовые T-блоки. По каждой секции проверять, не покрывается ли задача готовым блоком, прежде чем писать свой код.
- T123 со стилями — **выше** оформляемого блока. T123 со скриптами — в самый низ страницы.
- Над блоками с кодом — T218 «Системный комментарий». В цехе его роль выполняет баннер `T123 · СЕКЦИЯ: …`, текст которого копируется в T218 дословно.
- Проверять код можно **только на опубликованной** тестовой странице: в редакторе и предпросмотре T123 выводится текстом.

## 5. Стек

Библиотеки подключаются **один раз** через «Настройки сайта» → «Ещё» → «HTML-код внутрь head». В блоках не дублировать. Версии пинить полностью, до патча; ни `latest`, ни усечённые диапазоны вида `gsap@3.15`.

| Библиотека | Версия | URL |
|---|---|---|
| GSAP core | 3.15.0 | `https://cdn.jsdelivr.net/npm/gsap@3.15.0/dist/gsap.min.js` |
| ScrollTrigger | 3.15.0 | `https://cdn.jsdelivr.net/npm/gsap@3.15.0/dist/ScrollTrigger.min.js` |
| SplitText | 3.15.0 | `https://cdn.jsdelivr.net/npm/gsap@3.15.0/dist/SplitText.min.js` |

- Порядок подключения строгий: core первым, плагины после него. Без `defer`: инлайновый блок инициализации не откладывается и при `defer` выполнится раньше библиотек.
- GSAP с версии 3.13 бесплатен полностью, включая все плагины, в том числе для коммерческого использования.
- `gsap.registerPlugin(ScrollTrigger, SplitText)` вызывается один раз в блоке инициализации внизу страницы. В секциях не повторять. Плагины регистрируются независимо друг от друга: отсутствие одного не должно снимать регистрацию другого.
- ScrollTrigger работает на нативном скролле страницы. Библиотеки плавного скролла в стеке нет.
- Объём анимаций на мобильных меньше десктопного (VIS-7). Разводить через `gsap.matchMedia()`, а не дублированием кода.
- Узкие библиотеки (слайдер, лайтбокс, видеоплеер) добираются под конкретную секцию. Просто так в стек ничего не добавлять.
- Версии проверены на шаге 10: 3.15.0 — актуальный релиз GSAP, SplitText входит в публичный пакет.

**SplitText**

Используется для hover-эффектов ссылок. Правила действуют во всех секциях:

- сплит применяется только к тексту внутри секции; целевой элемент и все сгенерированные узлы остаются внутри её контейнера;
- имена сгенерированных классов задаются явно через `linesClass` / `wordsClass` / `charsClass` с префиксом секции (`sw-header__nav-char`). Дефолтные имена плагина не использовать: они не под нашим контролем;
- секция перед вызовом проверяет `window.gsap` и `window.SplitText` и тихо ничего не делает, если их нет;
- сплит по строкам запускается после готовности шрифта (`document.fonts.ready`) либо с `autoSplit: true`: при `font-display: swap` строки, посчитанные на фолбэк-шрифте, разъедутся в момент подмены на Inter;
- на интерактивных элементах (`<a>`, `<button>`) параметр `aria` задаётся явно. По умолчанию плагин вешает `aria-label` на разделяемый элемент, а на контролах это конфликтует с WCAG 2.5.3 «Label in Name»;
- обработчики событий вешаются на сам `<a>`, а не на сгенерированные узлы: при ре-сплите узлы пересоздаются и слушатели на них умирают. Прямо касается `reachGoal` по ANL-3;
- hover-эффекты живут только под `(hover: hover)` и `(min-width: 769px)` в `gsap.matchMedia()`; при `prefers-reduced-motion: reduce` сплит не запускается.

Активное состояние (`:active`) под `(hover: hover)` **не** прячется, где смена состояния несёт смысл: иначе на телефоне нажатие не даёт отклика. Касается плашек каналов связи. На iOS Safari `:active` не срабатывает без слушателя касания на самом элементе.

**Шрифт**

Inter подключается **настройками сайта Тильды**: «Шрифты и цвета» → «Расширенные настройки» → «Загрузить шрифт». Загружены `woff` и `woff2`, имя семейства — `Inter`.

Свой `@font-face` в head не объявляется: форма (FRM-4) и куки-баннер (LEG-4) — нативные блоки Тильды, их шрифт задаётся настройками сайта, и собственная декларация стала бы второй конкурирующей.

Имя семейства в настройках Тильды и первое имя в `--sw-font-family` совпадают **посимвольно**. Расхождение — секции молча уезжают на системный фолбэк, ошибки в консоли нет. Подробности и проверка — `design_system.md` раздел 4, требование — PRD NFR-7.

## 6. Контракты между секциями

Секции изолированы. Исключений ровно два, третьего не заводить.

**Контракт 1. Каталог → Форма.** Клик по карточке ведёт к форме с подставленным типом камня. Значения опций селекта совпадают с названиями позиций **посимвольно** — при расхождении подстановка молча не срабатывает. Полные условия: PRD 10.

**Контракт 2. GlobalHeader → Mobile\_menu.** Кнопка бургера живёт в шапке, открывает чужую секцию. Разделение жёсткое: GlobalHeader отдаёт только разметку кнопки с атрибутом `data-sw-menu-trigger` и своим `aria-expanded`, вся логика — открытие, блокировка скролла, переключение состояния — внутри Mobile\_menu. Предмет контракта — одно имя атрибута. Обе секции переживают отсутствие второй. Полные условия: PRD 10.3.

Блокировка скролла — единственное разрешённое обращение к корню документа, и только из JS, с сохранением и восстановлением прежних значений. Правила по `body` в CSS перенесённого кода по-прежнему запрещены.

**Источник названий позиций — имена файлов.** Отдельного списка позиций нет. Имя файла без расширения в `/Materials/Catalog` и есть название позиции. Оно попадает в разметку карточки, в значение опции селекта и в alt по шаблону. Связывание происходит один раз при сборке, не в рантайме: переименование фото после сборки требует правки кода. Та же механика в `/Materials/Photo` для портфолио. Подробности и непроверенное место с кириллицей — PRD 10.1.

Отдельно, не контракт: по BIZ-2 каналы связи стоят в GlobalHeader и в Footer. Это независимые секции с продублированной разметкой, общего состояния между ними нет. Но имена целей аналитики у обеих точек **одинаковые** — разойдутся имена, вместо одного счётчика получим два половинчатых. При смене номера телефона правка в обеих точках вручную: принято сознательно как цена изоляции.

## 7. Заголовки

Настройки «SEO: тег для заголовка» в блоках с нашим кодом нет — теги пишем руками, ошибиться легко.

- **Ровно одна H1 на всю страницу**, в Hero, содержит главный ключевой запрос.
- Слоган «Искусство вне времени» — **не заголовочный тег вообще.** Ни H1, ни H2. Только визуальный элемент, иначе конкурирует с H1.
- H2 — заголовок каждой секции. H3 — уровни внутри секции. Уровни не пропускаются.
- Заголовки — настоящие `h2`/`h3` с классами `sw-*`, не `div`.
- SplitText, применённый к заголовку, тег не меняет — но переписывает содержимое. Заголовочный тег обязан оставаться настоящим `h2`/`h3` и после сплита.

## 11. Поведение

- Не начинать работу, не создавать и не переписывать файлы без явной команды. Обсуждение ≠ разрешение действовать.
- Сначала план, потом исполнение. Для нетривиальной задачи — план и подтверждение.
- Требования заказчика **не додумывать.** Прямой связи с заказчиком нет, требования размытые, вкусы заказчика понимает пользователь. Неоднозначность → вопрос пользователю, а не собственный выбор.
- Только то, что запрошено. Без «полезных дополнений» сверх задачи.
- Решение, которое сломается при переносе в Тильду, называть сразу, до того как оно попадёт в документ или в код.
- Проект идёт по шагам, каждый шаг — отдельная сессия. Вперёд не забегать.
